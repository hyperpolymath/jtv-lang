== 1. Conformance summary — the honest headline

JtV is an *engineering-first* project with a *Lean-first* theory layer. Under the
estate's Theory Path, that combination currently reaches **no mathesis grade at
all**, for three independent reasons:

[cols="1,3",options="header"]
|===
| Estate leg | State in JtV

| Theory — *Agda* source of truth (PROOF-POLICY §1, §2)
| *Absent.* No `.agda` file in the tree. This is the one that matters: every
  mathesis grade (3, 2i, 2ii, 1) is defined on an Agda witness, so **with no Agda
  witness there is no grade to assign**, however strong the Lean work is.

| Theory — *Rocq* recheck leg
| *Absent.* No `.v` file, no Dedukti/Lambdapi transport.

| Theory — *Lean* recheck leg
| *Present and substantial* (7 libraries, no `sorry`/`admit`/added `axiom`,
  Mathlib-free). Under PROOF-POLICY §3 this is **target-only evidence**, not a
  leg: "until then it is target-only evidence, recorded with its own status, and
  the Agda row stays `OPEN`."

| Engineering — *Idris2* (ABIs, wire formats, totality)
| *Present.* `src/abi/Types.idr`, `%default total`, the Harvard GADT separation
  and the purity/widening orderings.

| Engineering — *Rust/Creusot* (contracts on first-party Rust)
| *Absent.* No Creusot contract, no `why3` artefact, no Creusot harness anywhere
  in `crates/`. Under §1 this is the mapping for JtV's core runtime.

| Engineering — *Kani* (standing exception: `unsafe`, FFI seams)
| *Absent* (see §4 rows K-1…K-2).
|===

*Status tokens used below* (closed vocabulary, PROOF-POLICY §5 /

`argued`, `open`. *Mathesis status tokens* (mathesis §6): `Open`, `Claimed`,

  (repo-reported) where they would otherwise be `Grade 1`-style receipts.
  PROOF-POLICY §2.3 is explicit that policy text "records a policy, not
  successful proof executions"; the same applies to this ledger.
. *Version pins for the re-verification claims:* Lean
  `leanprover/lean4:v4.12.0` (`jtv_proofs/lean-toolchain`), Idris2 as installed
  by `.github/workflows/proof-regression.yml` (distro package, `idris2-pack`

=== 1.1 What Grade 3 would require, concretely

Grade 3 = the theorem type-checks **locally in Agda** under the canonical
invocation (`agda --safe --without-K --cubical-compatible <module.agda>`,
PROOF-POLICY §2.1) and has **not** been translated to an independent foundation.
Note the consequence for JtV: because the Lean proofs already exist, the moment an
Agda witness for the same statement type-checks, JtV is *past* Grade 3 — it is at
Grade 2i (Lean leg present, statement correspondence recorded), with Grade 2ii
needing a non-DTT second leg (Isabelle/HOL) and Grade 1 needing a headless CI
checker API receipt. The binding obligation is therefore **Agda first**, not more
Lean.

== 5. Path to Grade 3 and beyond (sequenced per PROOF-POLICY §2.3)

Evidence-first order; each step keeps the existing gates green rather than
replacing them.

. *Keep the Lean and Idris2 gates exactly as they are.* They are the repository's
  only kernel-checked evidence and `proof-regression.yml` already runs them.
. *Take one exact theorem to Agda.* Not the whole suite: `dataExpr_totality`
  (structural recursion over the `DataExpr` GADT — no fancy library needed) or
  the Echo lattice laws (`Safe ⊑ Neutral ⊑ Breaking`, join is idempotent and
  associative). Pin `agda --safe --without-K --cubical-compatible` plus the stdlib
  version, and record both with the commit. **This single step is what converts
  `Claimed` into Grade 3.**
. *Then the Rocq leg* for that same statement (Dedukti transport via echidna's
  exchange layer, or hand re-proof — PROOF-POLICY §2 lets either stand, provided
  the route is recorded per theorem). That is Grade 2i.
. *Reconcile statements, don't just compile both.* Record, per theorem: exact
  proposition, assumptions, type/universe discipline, source revision, versions,
  invocation, observed result, and the declared route (`transported` /
  `re-proved`). A green build in both provers is **not** evidence they proved the
  same proposition (PROOF-POLICY §2.2). This is the obligation most likely to be
  skipped and it is the one that makes 2i mean anything.
. *Grade 2ii* additionally needs a non-DTT leg — Isabelle/HOL — because Agda,
  Rocq and Lean are all in the same DTT/CIC family and a second DTT leg buys no
  foundational diversity (mathesis §5).
. *Grade 1 / receipts* needs the headless checker API leg (AXLE for Lean,
  coq-lsp for Rocq, Isabelle server for HOL) plus the pinned commit hash, so
  mathesis can detect `Regressed`/`Superseded` states later.

=== 5.1 The Rust/Creusot route — and the Aeneas temptation

PROOF-POLICY §1 puts JtV's core runtime under Creusot: contracts and proofs on
the first-party Rust itself. None exist, so every behavioural claim about
`reversible.rs`/`interpreter.rs` is currently `tested-only` at best.

Aeneas is *the* estate route for "Rust code implements a theorem proved in a
proof assistant" (§4.1), which is exactly JtV's `gap-001`. It is **not** adoptable
today, and the reason is policy, not preference:

* Aeneas's Rocq backend carries an axiom (`mk_array`) from which `False` is
  derivable and is unmaintained → cannot support any status above `ASSUMED`.
* Aeneas's Lean backend depends on Mathlib, which §2 rules out estate-wide.
* Therefore the Rust↔model correspondence row is `ASSUMED` at best, and the
  model theorem stays `proven` only because its own kernel check is independent.

Recorded so a future session does not "close the proof-to-interpreter gap" with
Aeneas and then report the implementation as proved: per §4.1 that would be two
rows — `proven` for the model, `ASSUMED` for the correspondence — and needs a
recorded owner decision to adopt the backend at all.
