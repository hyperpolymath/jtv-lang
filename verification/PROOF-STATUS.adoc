The proof-status file for this repository, recording which prover carries which
obligation and the *strength* of each result, under the estate rules. It exists
because JtV claims proofs (README, EXPLAINME §7, AFFIRMATION), which makes a

*Normative sources — this file follows them, and where it disagrees with them
they win:*

* `hyperpolymath/standards` → `3-practice/PROOF-POLICY.adoc` — which prover
  carries which obligation (§1 mapping), how theory proofs are rechecked (§2),
  re-homing of existing proofs (§3), exceptions (§4), status vocabulary (§5).
* `hyperpolymath/standards` → `docs/README-EXPLAINME-STANDARD.adoc` §5 — the
  closed proof-ledger vocabulary.
* `hyperpolymath/mathesis` → `estate-mathematical-architecture` §5 (graded proof
  architecture) and §6 (epistemic precision, receipts, regressions).
* `verification/PROOF-CAPABILITY-MATRIX.adoc` — JtV's own detail matrix
  (per-library, per-theorem). This file is the ledger summary that matrix feeds.

== 1. Conformance summary — the honest headline

JtV was an *engineering-first* project with a *Lean-first* theory layer. As of
2026-11-01 it also has an **Agda theory layer** for part of its model
(`theory/agda/`, four modules, receipt in
`verification/receipts/2026-11-01-agda.adoc`), which is what makes a mathesis
grade assignable at all. The Lean layer remains — and remains valuable — but its
standing changed: the statements it covers now have an Agda source, so it is on
its way to being a *leg* rather than target-only evidence.

[cols="1,3",options="header"]
|===
| Estate leg | State in JtV

| Theory — *Agda* source of truth (PROOF-POLICY §1, §2.1)
| *Present for four modules* (`Jtv.Core`, `Jtv.Reversal`, `Jtv.Echo`,
  `Jtv.Conditional`), checked with the canonical invocation, no holes or
  postulates, pinned Agda 2.7.0.1 + stdlib 2.4. Covers the Data-fragment model,
  the Safe/Neutral reversal theorems, the Echo lattice + fibre, and the

  neither Rust nor Creusot could be installed. Recorded, not worked around.

| *Absent* (rows K-1…K-2).

== 3. Verification commands and their toolchain requirements

[source,bash]
----
# Theory (Agda — the estate source of truth; this is the receipted one)
( cd theory/agda && ./check.sh )     # pin: Agda 2.7.0.1, agda-stdlib 2.4

# Theory (Lean leg, target-only evidence) — run from the repo root: a bare
# `cd jtv_proofs` would persist and break the commands below it.
( cd jtv_proofs && lake build )      # pin: leanprover/lean4:v4.12.0
grep -rnwE 'sorry|admit|axiom' jtv_proofs/*.lean   # must be empty

# Engineering (Idris2 ABI)
idris2 --check src/abi/Types.idr

# Engineering (Rust behaviour — tested-only)
cargo test --all

# Theory (Agda) — the canonical invocation is the script, not a bare agda call:
# it supplies the library configuration and the hole/postulate scan.
(cd theory/agda && ./check.sh)
----

*Toolchain honesty (PROOF-POLICY §6).* A session without Agda, Rocq/Lambdapi, or
Creusot/Why3 **cannot run those legs**, and must say so rather than report them
passing. The session that wrote this ledger had none of them. Adding them belongs
in `setup.sh` (agent sessions) and the Guix manifest/container (CI) per
`standards/LANGUAGE-POLICY.adoc` §2.

*Recorded deviation — CI install route.* `.github/workflows/agda-proof-policy.yml`
builds Agda 2.7.0.1 and agda-stdlib 2.4 from upstream tagged sources rather than
through a Guix manifest or container, because this repository has no such
manifest or Agda image (the only `Containerfile` is ClusterFuzzLite's). The job
compensates by asserting the *installed* stdlib library name against this
project's `depend: standard-library-2.4`, so a silent substitution fails rather
than passes. This is a documented exception, not compliance; the remediation is
an Agda entry in the estate manifest. The same workflow notes why its action
references stay version-tagged (the repository's `actions.lock` is generated from
tags) and takes the credential half of that fix (`persist-credentials: false`).

== 5. Path to Grade 3 and beyond (sequenced per PROOF-POLICY §2.3)

Evidence-first order; each step keeps the existing gates green rather than
replacing them. *Progress 2026-11-01: steps 1–2 done, step 3 next.*

. *Keep the Lean and Idris2 gates exactly as they are.* ~Done~ — unchanged;
  `proof-regression.yml` still runs them.
. *Take exact theorems to Agda.* *Done for four modules* — not just the Echo
  lattice: `Jtv.Core` (evaluation independence), `Jtv.Reversal` (Safe and
  Neutral tiers plus the necessity counterexample), `Jtv.Echo` (lattice, both
  admissibility policies, the block theorem, the retained-loss fibre), and
  `Jtv.Conditional` (the tokenless-`if` counterexample). Pinned Agda 2.7.0.1 +
  stdlib 2.4; receipt filed. New gate: `.github/workflows/agda-proof-policy.yml`.
  *Remaining port work:* `dataExpr_totality` (the structural induction itself —
  the current modules prove evaluation independence, not totality), the
  `isIntRepr` type-preservation family, `JtvSecurity`'s AOLD bundle, and
  `JtvExtended`.
. *Then the Rocq leg* for that same statement (Dedukti transport via echidna's
  exchange layer, or hand re-proof — PROOF-POLICY §2 lets either stand, provided
  the route is recorded per theorem). *This supplies the Rocq leg required for
  Grade 2i — it does not by itself award the grade:* the reconciliation in the
  next step is what makes 2i mean anything, and it is still outstanding.
. *Reconcile statements, don't just compile both.* Record, per theorem: exact
  proposition, assumptions, type/universe discipline, source revision, versions,
  invocation, observed result, and the declared route (`transported` /
  `re-proved`). A green build in both provers is **not** evidence they proved the
  same proposition (PROOF-POLICY §2.2). This is the obligation most likely to be
  skipped and it is the one that makes 2i mean anything.
. *Grade 2ii* additionally needs a non-DTT leg — Isabelle/HOL — because Agda,
  Rocq and Lean are all in the same DTT/CIC family and a second DTT leg buys no
  foundational diversity (mathesis §5).
. *Grade 1 / receipts* needs the headless checker API leg (AXLE for Lean,
  coq-lsp for Rocq, Isabelle server for HOL) plus the pinned commit hash, so
  mathesis can detect `Regressed`/`Superseded` states later.

=== 5.1 The Rust/Creusot route — and the Aeneas temptation

PROOF-POLICY §1 puts JtV's core runtime under Creusot: contracts and proofs on
the first-party Rust itself. None exist, so every behavioural claim about
`reversible.rs`/`interpreter.rs` is currently `tested-only` at best.

Aeneas is *the* estate route for "Rust code implements a theorem proved in a
proof assistant" (§4.1), which is exactly JtV's `gap-001`. It is **not** adoptable
today, and the reason is policy, not preference:

* Aeneas's Rocq backend carries an axiom (`mk_array`) from which `False` is
  derivable and is unmaintained → cannot support any status above `ASSUMED`.
* Aeneas's Lean backend depends on Mathlib, which §2 rules out estate-wide.
* Therefore the Rust↔model correspondence row is `ASSUMED` at best, and the
  model theorem stays `proven` only because its own kernel check is independent.

Recorded so a future session does not "close the proof-to-interpreter gap" with
Aeneas and then report the implementation as proved: per §4.1 that would be two
rows — `proven` for the model, `ASSUMED` for the correspondence — and needs a
recorded owner decision to adopt the backend at all.
