== Global rules for every wave

* Holes before features. A new hole freezes the feature lanes.
* One worktree per implementer: `git worktree add <scratchpad>/wt-<lane> -b claude/jtv-w<N>-<lane>`.
* File ownership is declared in each brief. An agent touching a file it does not own stops and reports.
* Every gate is a command with an exit code. A count gate compares the printed number (`wc -l` or `test "$(...)" -eq N`); it never relies on grep's exit status, which is 1 when nothing matches. A red gate after two fix attempts stops that lane.
* The interpreter is the reference. Suspected interpreter bugs are logged, never papered over.
* No `sorry`, `admit`, `native_decide`, new axioms or `believe_me`.
* No licence or SPDX edits to existing files. New docs: CC-BY-SA-4.0. New code: MPL-2.0 (LICENSING.adoc table).
* Only the clean-checkout verifier may flip a ledger row to LANDED.

Global stop conditions: unsigned commit; licence edit; third-party code; push outside jtv-lang; admin merge; denied toolchain faked as green; IS/IS-NOT violation; typed-wasm `--reseal` or abi bump; unexplained differential disagreement.

The Gate column summarises each lane. The executable form is `LANES[n].gate` in the workflow skeleton below: one shell command per entry, each with its own exit code, and a lane is ready only when every entry exits 0, both in the implementer's report and when the reviewer re-runs the full list. That list is authoritative. Rejections everywhere mean the CLI's handled `JtvError` status 1; any other non-zero status (101 panic, 134 abort, 124 timeout) is a crash. The REPL falsifier is driven with `:load <file>` then `:quit`, so the REPL sees the file as one program.

*Adversarial reviewer (one agent, no worktree, read-only).* Writes falsifiers first, before implementers finish: mutual f→g→f; Data → `@total` → `@pure` loop; recursion via `M::f`; shadowing; caller-local read; reverse in function; impure-in-Data via wasm and REPL; Symbolic, String and Any reverse; deep Impure recursion; blow-up tree; nesting bomb; extern intrinsic in Data; re-entrant JS callback; overwrite inside a reversible `if`; guard that flips under its own branch. Any surviving falsifier blocks merge.

*Merge order.* A → D → G → B → E-interim → C → E → F (G needs A and D merged; E-interim needs B, and also G outside the STOP rule, because both own `interpreter.rs`; E needs B, C and E-interim). E rebases on B and C. The lead resolves conflicts. Lane branches are merged with merge commits, never squashed, so each dependent lane can prove its prerequisites with `git merge-base --is-ancestor` (the first commands of its gate).

== Workflow script skeleton (Wave 0 and Wave 1)

Plain JavaScript for the Workflow tool. Like any Workflow script it is an async function body (it ends in a top-level `return`), so it is syntax-checked that way: wrapped in `export default async function (...) { ... }` it passes `bun build --no-bundle`, and the bare file is not a standalone module. Fill `repo` (the absolute path of the jtv-lang checkout), `scratch` and the branch names when running it. Each run does one mode. The lead merges branches between runs, so ordering is enforced by checked prerequisites, not by prose.

[cols="1,3",options="header"]
|===
|Run |What it does

|`{ mode: 'wave0', repo, scratch }`
|Run with HEAD at the pre-Wave-1 commit. Records that commit's SHA in `<scratch>/receipts/pre-wave1.sha`, then writes the W0 receipt, the census, X11, the parse and depth sweep, and the lane-tagged falsifiers. No source change. `scratch` must be an absolute path shared by every worktree. Every later mode requires `baseline` and an explicit `openHoles` list, which must be empty: any untriaged hole from an earlier run freezes the next run.

|`{ mode: 'lanes', repo, scratch, baseline, baselineTests, signing, stopRule: false, openHoles: [], lanes: ['grammar', 'carrier', 'wasm', 'purity', 'proof-hygiene'], base, merged: [] }`
|Independent lanes, one worktree each, branched from `base`. Each reviewer checks out that lane's branch in its own worktree and runs only that lane's falsifiers.

|`{ mode: 'lanes', repo, scratch, baseline, baselineTests, signing, stopRule: false, openHoles: [], lanes: ['reversible-if'], base, merged: ['grammar', 'carrier', 'wasm'] }`
|Dependent lanes start from an integration branch that already contains their prerequisites. The script refuses to start a lane whose prerequisites are not listed as merged.

|`{ mode: 'lanes', repo, scratch, baseline, baselineTests, signing, stopRule: false, openHoles: [], lanes: ['entry-interim'], base, merged: ['grammar', 'carrier', 'wasm', 'reversible-if'] }`
|After `reversible-if` merges. Both lanes own `interpreter.rs`, so outside the STOP rule `entry-interim` starts from a base that already contains it.

|`{ mode: 'lanes', repo, scratch, baseline, baselineTests, signing, stopRule: false, openHoles: [], lanes: ['entry'], base, merged: ['grammar', 'carrier', 'wasm', 'reversible-if', 'entry-interim', 'purity'] }`
|The `CheckedProgram` typestate, after the purity lane. Outside the STOP rule `reversible-if` is a direct prerequisite too, because an `entry-interim` built under the STOP rule does not contain it and both lanes edit `interpreter.rs`.

|`{ mode: 'lanes', repo, scratch, baseline, baselineTests, signing, stopRule: true, openHoles: [], lanes: [...], base, merged: [...] }`
|STOP-rule runs: only `grammar`, `wasm` and `entry-interim` may run (H2, H11, H12, H13 and the interim H1). Anything else throws. `stopRule` is required in every `lanes` run; omitting it throws, so a missing owner answer can never read as permission.

|`{ mode: 'gate1', repo, scratch, baseline, baselineTests, openHoles: [], integration, base: '<the SHA in receipts/pre-wave1.sha>', signing: 'environment' or 'owner-key', merged: [all eight lanes], stopRule: false }`
|Gate 1 on the merged branch: full test, lint, format and wasm32 build; trybuild; probes in `--gate` mode; the Lean axiom audit; every falsifier with its expectation; census delta against the baseline. With `stopRule: true`, `merged` may hold only the STOP lanes and only their falsifiers are judged. A second agent tries to refute the report. `green` is true only if the report lists exactly the required Gate 1 commands, each exited 0, each falsifier appears exactly once with its expectation met, the test count is at least the baseline count, every commit is signed under the Q36 ruling, neither agent reported a new hole, and the refutation failed.
|===

Lane mapping to the Wave 1 table: A = `grammar`, B = `wasm`, C = `purity`, D = `carrier`, E = `entry-interim` then `entry`, F = `proof-hygiene`, G = `reversible-if`.

Notes on the skeleton:

* Merging is done by the lead between runs, not by agents. That keeps doctrine 5 and the signing rule in human view.
* A lane is reported `readyToMerge` only if its reviewer did not refute it, every gate exit code was 0, and no new hole was reported in that run.
* Any non-empty `newHoles` freezes later lanes until the lead triages it.
* Re-run with `resumeFromRunId` after an edit; unchanged agent calls return cached results. A new `base` or `merged` value changes the prompts, so those agents re-run.

== Budget and pacing

* *Wave 0:* one session. Mostly read-only; cheap.
* *Wave 1:* two to three sessions. Six implementers plus one reviewer. The purity lane is the long pole; give it one agent and `effort: high` on review.
* *Wave 2:* two sessions. *Wave 3:* two sessions (Lean CI round-trips cap at 3 per wave). *Wave 4:* two sessions. *Wave 5:* one to two sessions, mostly drafts.
* *Total:* roughly 10–13 sessions to Gate 5. The critical path to an honest, usable, embedded and demoable system is Waves 0–3 (about 7–10 sessions).
* Prefer `pipeline()` over barriers. Use worktree isolation only for agents that write files.
* Use `effort: 'low'` for receipt and grep stages; `'high'` for reviewers and the Lean lane.
* Stop a lane after two failed fix attempts; do not spend budget retrying the same approach.

== What to report at the end of each wave

. *Gate table:* each gate command, exit code, and where the receipt lives.
. *Holes:* closed, still open, and any new ones (new ones freeze feature lanes).
. *Ledger delta:* rows changed, with the clean-checkout verifier's confirmation. Nothing says "verified" without a receipt.
. *Census delta:* corpus pass counts vs the Wave 0 baseline (examples, conformance/check, stdlib).
. *Branches and PRs:* branch names, signature status, PRs proposed (not opened without owner OK).
. *Owner questions:* answered, still pending, and new ones, each with its labelled default arm.
. *Cross-repo list:* drafts prepared, repo, and what each blocks.
. *Toolchain status:* what ran locally, what is CI-pending.
. *Next wave's first step,* and anything that changes its scope.
